## 1. 架构概览

金融业务微服务系统（个人账户/统计/通知），已从 Spring Cloud Netflix 栈整体迁移至 Spring Cloud Alibaba + Nacos 栈。

| 维度 | 重构前 | 重构后 |
|---|---|---|
| JDK | 1.8 | 17 (LTS) |
| Spring Boot | 2.0.3.RELEASE | 3.5.3 |
| Spring Cloud | Finchley.RELEASE | 2025.0.0 |
| Spring Cloud Alibaba | — | 2025.0.0.0 |
| 注册中心 | Eureka (registry 模块) | Nacos 3.0.3 discovery |
| 配置中心 | Config Server (config 模块, native classpath) | Nacos 3.0.3 config（namespace 按环境隔离） |
| 网关 | Zuul 1 (阻塞) | Spring Cloud Gateway (WebFlux/Netty) |
| 熔断降级 | Hystrix + Turbine | Sentinel 1.8.9（Feign 集成 + 网关流控） |
| 认证 | spring-security-oauth2 + InMemoryTokenStore + NoOp | Spring Authorization Server 1.5.1 + JWT(RS256) + BCrypt |
| 资源服务器 | user-info 回调 (CustomUserInfoTokenServices) | 本地 JWT/JWK 校验（无网络往返） |
| 链路追踪 | Sleuth | Micrometer Tracing (bridge-brave)，traceId/spanId 入日志 |
| 消息 | RabbitMQ (bus-amqp + turbine) | 已移除（无业务用途） |
| 定时任务 | @Scheduled 无锁 | @Scheduled + ShedLock 7.10.1 (Mongo provider) |
| 模块数 | 9 | 5（gateway/auth/account/statistics/notification）+ mongodb 初始化镜像 |
| 存储 | MongoDB 4.4（4 个独立实例，库私有） | MongoDB 数据层未变更，wire-compatible |

服务间调用关系（与重构前一致，未变更业务拓扑）：
- account-service → auth-service（POST /uaa/users，开户时创建用户）
- account-service → statistics-service（PUT /statistics/{accountName}，账务变更后更新统计）
- notification-service → account-service（GET /accounts/{accountName}，取备份附件）
- statistics-service → 外部汇率 API（GET {rates.url}/latest）
- gateway → 4 个服务（/uaa 固定 URL；其余 lb:// 经 Nacos 负载均衡）

## 3. 认证与授权架构

### 3.1 令牌流

```
[UI/浏览器] --password grant(legacy 扩展)--> auth-service /uaa/oauth2/token
                                              -> JWT access_token (RS256, scope=ui) + opaque refresh_token
[服务间]   --client_credentials-------------> auth-service /uaa/oauth2/token
                                              -> JWT access_token (scope=server)
[资源服务器] 收到 Bearer JWT -> 本地 JWK 校验（issuer=http://auth-service:5000/uaa）
                                              -> authorities 含 SCOPE_server / SCOPE_ui
                                              -> @PreAuthorize("hasAuthority('SCOPE_server')") 生效
```

### 3.2 客户端注册（等价迁移，未变更授权语义）

| clientId | grant types | scope | 认证方式 |
|---|---|---|---|
| browser | password(legacy扩展), refresh_token | ui | NONE（公共客户端） |
| account-service | client_credentials, refresh_token | server | client_secret_basic / post，BCrypt 存储 |
| statistics-service | 同上 | server | 同上 |
| notification-service | 同上 | server | 同上 |

### 3.3 关键端点变化（对外行为差异，集成方须知）

| 用途 | 旧 | 新 |
|---|---|---|
| 令牌端点 | /uaa/oauth/token | /uaa/oauth2/token |
| JWKS | 无（opaque token） | /uaa/oauth2/jwks |
| 授权码端点 | /uaa/oauth/authorize | /uaa/oauth2/authorize |
| 令牌校验 | /uaa/oauth/check_token | 已移除（改为本地 JWT 校验） |

网关路由前缀 /uaa/** 未变，端点路径差异在网关下游。

### 3.4 授权规则（逐条等价，未放宽）

| 端点 | 规则 |
|---|---|
| account GET /{name} | SCOPE_server 或 name==demo |

## 4. 数据架构

- 4 个 MongoDB 实例，库名统一 piggymetrics，集合私有：users / accounts / datapoints / recipients(+shedlock)。
- 主键策略（未变更）：accounts._id = 账户名(String)；users._id = 用户名；recipients._id = accountName；datapoints._id = 复合 DataPointId{account, date}。
- Spring Data MongoDB 4.x：DBObject 转换器已改为 org.bson.Document（@ReadingConverter/@WritingConverter），持久化字段名 date/account 不变，存量数据可直接读取（wire-compatible）。
- CustomConversions → MongoCustomConversions（Bean 类型变更，注册内容不变）。
- 事务边界：**与重构前一致，仍无事务**。Mongo 单文档写原子；跨服务写（开户、账务-统计联动）无分布式事务、无补偿。此为已知高风险缺陷（H1/H2/H4），按人工确认本次不改造，另行立项。

## 6. 遗留架构风险（重构后仍存在，须立项跟踪）

| 编号 | 风险 | 级别 | 现状 |
|---|---|---|---|
| H1 | 开户链路跨服务写无事务/补偿/幂等（孤儿用户） | 🔴 高 | 未改造（等价迁移） |
| H2 | 账务保存与统计更新最终一致性无保障，fallback 静默吞错 | 🔴 高 | 未改造 |
| H3 | 金额换算精度策略（scale=4/HALF_UP、多次换算累积误差） | 🔴 高 | 算法零改动，仅做数值一致性锁定 |
| H4 | 降级策略缺补偿队列/对账 | 🔴 高 | 未改造 |
| H5 | Account 模型缺审计字段（版本号/操作流水） | 🔴 高 | 未改造 |
| H6 | JWT 签名密钥为启动时生成（JwtKeyProvider），多实例互不信任；client secret/Mongo/SMTP 密码走 env 明文 | 🔴 高 | **生产前必须整改**：密钥入 KMS/Nacos 加密配置并支持轮换 |
| H7 | 索引类数据变更（开户幂等唯一索引） | 🔴 高 | 未实施，须 DBA 审核 |
| D16 | 外部汇率数据源 api.exchangeratesapi.io 已停服 | 中 | 未变更数据源；上线前须业务确认；fallback 空 rates 会导致 getCurrentRates NPE（与旧版行为一致） |
| R9 | DataPoint 同日覆盖写 | 低 | 语义保留未改 |
| — | RecipientRepository $where 依赖 server-side JS | 中 | 保留；托管 Mongo 可能禁用，建议改聚合查询 |
| — | mongodb 初始化镜像仍 mongo:4.4 + legacy mongo shell | 低 | 原样保留，避免破坏 seeding；建议独立立项升级 mongosh |
| — | InMemoryOAuth2AuthorizationService（refresh 簿记在内存） | 中 | 与旧 InMemoryTokenStore 等价未恶化；严格会话管理属 H6 |

## 7. 演进路线建议（不在本次范围）

1. H6 密钥治理（阻塞生产上线，优先级最高）。
2. H1/H2/H4：引入本地消息表 + RocketMQ 可靠投递 + 对账任务，实现开户与账务-统计的最终一致性与可追溯。
3. H5：Account 增加版本号（乐观锁）、操作流水集合，满足审计可追溯。
4. H3：制定全链路金额精度规范（统一 scale/RoundingMode/中间结果策略）并做数据回填验证。
5. 汇率数据源替换为可审计的银行内部牌价服务，增加牌价快照与生效时间留痕。
6. MongoDB 7.x + mongosh 初始化改造；$where → 聚合管道。
7. 补充 API 版本管理、灰度发布（可用 MSE/SCG 权重路由）。
