## 1. 架构概览

金融业务微服务系统（个人账户/统计/通知），已从 Spring Cloud Netflix 栈整体迁移至 Spring Cloud Alibaba + Nacos 栈，并在等价迁移基础上，对两个已知分布式一致性缺口落地了**方案A 幂等补偿 + 对账自愈**（成功路径零改动）。

| 维度 | 重构前 | 重构后 |
|---|---|---|
| JDK | 1.8 | 17 (LTS) |
| Spring Boot | 2.0.3.RELEASE | 3.5.3 |
| Spring Cloud | Finchley.RELEASE | 2025.0.0 |
| Spring Cloud Alibaba | — | 2025.0.0.0 |
| 注册中心 | Eureka | Nacos 3.0.3 discovery |
| 配置中心 | Config Server (native) | Nacos 3.0.3 config（namespace 按环境隔离） |
| 网关 | Zuul 1 | Spring Cloud Gateway（WebFlux/Netty）+ Sentinel 网关流控 |
| 熔断降级 | Hystrix + Turbine | Sentinel（Feign 集成 + 网关流控） |
| 认证 | spring-security-oauth2 + InMemoryTokenStore + NoOp | Spring Authorization Server 1.5.1 + JWT(RS256) + BCrypt |
| 资源服务器 | user-info 回调 | 本地 JWT/JWK 校验（无网络往返） |
| 链路追踪 | Sleuth | Micrometer Tracing（联调 Jaeger / 生产 SkyWalking Agent） |
| 分布式一致性 | 无事务、无补偿（孤儿用户/统计漂移） | **方案A：失败路径幂等补偿 + 对账自愈 Job** |
| 定时任务 | @Scheduled 无锁 | @Scheduled + ShedLock 7.10.1（Mongo provider） |
| 模块数 | 9 | 5（gateway/auth/account/statistics/notification） |
| 存储 | MongoDB 3.x | MongoDB 4.4（4 实例，库私有，wire-compatible 零迁移） |

服务间调用关系：
- account-service → auth-service（`POST /uaa/users` 开户建用户；`DELETE /uaa/users/{username}` 补偿删除孤儿用户）
- account-service → statistics-service（`PUT /statistics/{accountName}` 账务变更后更新统计；补偿 Job 经无 fallback 客户端重算）
- notification-service → account-service（`GET /accounts/{accountName}` 取备份附件）
- statistics-service → 外部汇率 API（`GET {rates.url}/latest`）
- gateway → 4 服务（/uaa 固定 URL；其余 lb:// 经 Nacos 负载均衡）

## 3. 认证与授权架构

### 3.1 令牌流

```
[UI/浏览器] --password grant(legacy 扩展)--> auth-service /uaa/oauth2/token
                                              -> JWT access_token (RS256, scope=ui) + opaque refresh_token
[服务间]   --client_credentials-------------> auth-service /uaa/oauth2/token
                                              -> JWT access_token (scope=server)
[资源服务器] 收到 Bearer JWT -> 本地 JWK 校验（issuer=http://auth-service:5000/uaa）
                                              -> authorities 含 SCOPE_server / SCOPE_ui
                                              -> @PreAuthorize("hasAuthority('SCOPE_server')") 生效
```

### 3.2 客户端注册（等价迁移，未变更授权语义）

| clientId | grant types | scope | 认证方式 |
|---|---|---|---|
| browser | password(legacy扩展), refresh_token | ui | NONE（公共客户端） |
| account-service | client_credentials, refresh_token | server | client_secret_basic / post，BCrypt 存储 |
| statistics-service | 同上 | server | 同上 |
| notification-service | 同上 | server | 同上 |

### 3.3 关键端点变化（对外行为差异，集成方须知）

| 用途 | 旧 | 新 |
|---|---|---|
| 令牌端点 | /uaa/oauth/token | /uaa/oauth2/token |
| JWKS | 无（opaque token） | /uaa/oauth2/jwks |
| 授权码端点 | /uaa/oauth/authorize | /uaa/oauth2/authorize |
| 令牌校验 | /uaa/oauth/check_token | 已移除（本地 JWT 校验） |
| 补偿删除（新增） | 无 | DELETE /uaa/users/{username}（SCOPE_server，幂等） |

### 3.4 授权规则（逐条等价，未放宽）

| 端点 | 规则 |
|---|---|
| account GET /{name} | SCOPE_server 或 name==demo |
| account GET/PUT /current | 已认证（principal 限定自身） |
| account POST / 、GET / 、/demo | permitAll（沿用旧配置） |
| statistics PUT /{accountName} | SCOPE_server |
| statistics GET /{accountName} | SCOPE_server 或 accountName==demo |
| statistics GET /current | 已认证 |
| auth POST /users | SCOPE_server |
| auth DELETE /users/{username} | SCOPE_server（与 createUser 同级最严权限） |
| notification /recipients/current | 已认证 |

## 4. 数据架构

- 4 个 MongoDB 实例，库名统一 `piggymetrics`，集合私有：`users` / `accounts` / `datapoints` / `recipients`(+`shedlock`)；account 库新增 `compensation-tasks`（方案A 任务表）。
- 主键策略（未变更）：accounts._id = 账户名(String)；users._id = 用户名；recipients._id = accountName；datapoints._id = 复合 DataPointId{account, date}；compensation-tasks._id = Mongo ObjectId。
- Spring Data MongoDB 4.x：DBObject 转换器已改为 org.bson.Document（@ReadingConverter/@WritingConverter），持久化字段名 date/account 不变，存量数据 wire-compatible 零迁移。
- CustomConversions → MongoCustomConversions（Bean 类型变更，注册内容不变）。
- 事务边界：Mongo 单文档写原子；**跨服务写仍无 ACID 分布式事务**（Seata AT 不适用 MongoDB，官方支持列表已核实）。方案A 以「失败路径幂等补偿 + 对账自愈」收敛两个具体一致性缺口，详见第 5 节。

## 5. 数据一致性架构（方案A：幂等补偿 + 对账自愈）

### 5.1 背景与边界

阶段1 实证了两个跨服务一致性缺口（无事务、无补偿所致）：
1. **孤儿用户**：开户时先写 auth 库用户、后写 account 库账户；账户写失败则 auth 侧遗留孤儿用户。
2. **statistics 静默漂移**：账务变更后 Feign 调 statistics 失败被 Sentinel fallback 吞掉，统计永久丢失。

方案A 只修失败路径，**成功路径调用顺序逐字保留**（红线守护）；未引入新中间件（无 Seata/RocketMQ）。

### 5.2 补偿域模型与状态机

| 概念 | 位置 | 说明 |
|---|---|---|
| `CompensationTask` | account-service domain | Type: `DELETE_AUTH_USER` / `UPDATE_STATISTICS`；Status: `PENDING`→`DONE`/`FAILED`；审计字段 attempts/lastError/createdAt/lastAttemptAt；集合 `compensation-tasks` |
| `CompensationTaskRepository` | account-service | 任务存取 + `findByTypeAndAccountNameAndStatus` 查重（幂等入队保障） |
| `CompensationReconciliationJob` | account-service | `@Scheduled(fixedDelay=30s)` 扫 PENDING → 执行补偿 → DONE；失败 attempts++ 重试；超 max-attempts(5) → FAILED + ERROR 级 `COMPENSATION ALERT` |
| `StatisticsCompensationClient` | account-service client | **无 Sentinel fallback** 的统计补偿客户端（contextId 区分），使 Job 感知真实失败而不误标 DONE |

### 5.3 两条补偿链路

**孤儿用户自愈**：
```
create() 成功路径：findByName → authClient.createUser → repository.save（不变）
失败路径：repository.save 抛异常 → 立即 authClient.deleteUser 补偿
        → 补偿也失败 → 入队 DELETE_AUTH_USER(PENDING) → 对账 Job 重试 → DONE
auth 侧 deleteByUsername 幂等：存在则删返回 true + WARN 审计日志；不存在返回 false
```

**statistics 漂移自愈**：
```
saveChanges() 成功路径：本地 save → statisticsClient.updateStatistics（不变）
失败路径（fallback 吞错）：fallback 入队 UPDATE_STATISTICS(PENDING)
失败路径（裸异常）：catch 入队后重抛（异常语义不变）
对账 Job：从真相源（account 文档）经无 fallback 客户端幂等重算 datapoint → DONE
```

### 5.4 幂等与可追溯保证

- 入队幂等：已有同 (type, accountName, PENDING) 任务则不重复入队。
- 执行幂等：delete 不存在即 no-op；重算同输入同输出。
- 可追溯：补偿删除记 WARN 审计日志（含 `COMPENSATION` + username）；FAILED 记 ERROR `COMPENSATION ALERT`（供 SkyWalking/Sentinel 接警）。

## 6. 韧性与可观测性

| 能力 | 实现 |
|---|---|
| 熔断/降级 | Sentinel（feign.sentinel.enabled=true），fallback 保留原有保可用性语义 + 方案A 入队补偿 |
| 网关流控 | spring-cloud-alibaba-sentinel-gateway，Dashboard :8858，超限 429 |
| 超时 | gateway connect 20s / response 20s（等价旧 zuul+ribbon 20s） |
| 链路追踪 | Micrometer Tracing bridge-brave（联调 Jaeger :16686）；生产 SkyWalking 10.2.0 Java Agent（OAP+MySQL，采样率差异化，6 条告警规则） |
| 健康检查 | actuator health/info/metrics（gateway 另暴露 gateway 端点） |
| 配置热更新 | Nacos config + @RefreshScope（EmailServiceImpl）；Feign url/JWT issuer/路由类需重启生效 |
| 定时任务互斥 | ShedLock Mongo provider（lock 集合 shedlock，lockAtMostFor 30M / lockAtLeastFor 5M） |

## 8. 遗留架构风险

| 编号 | 风险 | 级别 | 现状（v2.2） |
|---|---|---|---|
| H1 | 开户跨服务写无 ACID 事务 | 🔴 高 | 孤儿用户缺口已由方案A自愈；竞态/幂等键仍待立项（唯一索引 H7） |
| H2 | 账务-统计最终一致性 | 🔴 高 | 静默漂移缺口已由方案A自愈；可靠投递（消息表/RocketMQ）仍待立项 |
| H3 | 金额换算精度策略 | 🔴 高 | 算法零改动，黄金数据逐分锁定 |
| H4 | 降级补偿队列 | 🔴 高 | 已落地方案A补偿队列 + 对账 Job（原「仅日志」升级） |
| H5 | Account 缺审计字段 | 🔴 高 | 未改造（版本号/操作流水） |
| H6 | JWT 密钥启动时生成 + secret 走 env | 🔴 高 | **生产阻塞**：须 KMS/Nacos 加密配置 + 轮换 |
| H7 | 开户幂等唯一索引 | 🔴 高 | 未实施，须 DBA 审核 |
| D16 | 汇率源已停服 | 中 | rates-mock 联调替代；生产须接入有效牌价源（fallback 空 rates NPE 为已知现状 K2） |
| R9 | DataPoint 同日覆盖写 | 低 | 语义保留未改 |
| — | RecipientRepository $where 依赖 server-side JS | 中 | 建议改聚合查询 |
| — | mongodb 初始化镜像 mongo:4.4 + legacy shell | 低 | 仅开发 seeding，建议独立立项升级 mongosh |
| — | InMemoryOAuth2AuthorizationService（refresh 簿记内存） | 中 | 与旧 InMemoryTokenStore 等价未恶化，属 H6 |
| — | 对账 Job 多实例无锁 | 中 | 单实例 compose 无问题；多实例须 ShedLock 或单实例开启 |

## 9. 演进路线（不在本次范围）

1. H6 密钥治理（阻塞生产上线，优先级最高）。
2. H1/H2 深化：本地消息表 + 可靠投递（RocketMQ），替代"补偿任务表轮询"为事件驱动最终一致性。
3. H5：Account 增加版本号（乐观锁）、操作流水集合，满足审计可追溯。
4. H3：制定全链路金额精度规范（统一 scale/RoundingMode/中间结果）并数据回填验证。
5. 汇率数据源替换为可审计的银行内部牌价服务，增加牌价快照与生效时间留痕。
6. 对账 Job 多实例分布式锁；compensation-tasks 加 TTL 索引清理 DONE 历史。
7. MongoDB 7.x + mongosh 初始化改造；$where → 聚合管道。
8. 补充 API 版本管理、灰度发布（MSE/SCG 权重路由）。
