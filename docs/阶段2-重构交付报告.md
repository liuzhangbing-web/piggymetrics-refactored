## 七、遗留风险与后续事项（如实报告）

1. 🔴 H6（安全红线，另行立项）：JwtKeyProvider 当前为每次启动生成 RSA 密钥对——多实例部署会导致互相无法校验对方签发的 token。生产前必须改为从 KMS/Nacos 加密配置加载固定密钥。代码中已注释标记。
2. 🔴 H1/H2/H3/H4/H5：开户链路无补偿、账务-统计最终一致性、fallback 静默吞错、审计字段——按确认全部未动，另行立项。
3. InMemoryOAuth2AuthorizationService：refresh token 簿记在内存，重启后 refresh 失效（access token JWT 无状态不受影响）。与旧 InMemoryTokenStore 行为等价，未变差；如需严格会话管理属 H6 范围。
4. D16：外部汇率 API api.exchangeratesapi.io 已停服，运行期 ExchangeRatesClient 将走 fallback（空 rates → getCurrentRates 会 NPE，与旧版行为一致）。上线前必须确认新数据源，属业务决策，未擅自变更。
5. B5（联调阶段发现，已修复）：nacos-config/sync 配置模板中密码占位符曾被写入损坏（${VAR:***），导致 Mongo 认证失败；已重建为 ${VAR:} 并对 dev/it 双命名空间重新发布+读回校验。教训已沉淀：配置模板发布前必须过 YAML 合法性与占位符完整性检查。
6. RecipientRepository $where 依赖 server-side JavaScript，MongoDB 7.0 默认可用但部分托管服务禁用；建议后续立项改为聚合查询。
6. 测试代码（src/test）未迁移——按流程属阶段3 deepseek 生成，本工程 test 目录为空，mvn test 将只跑上下文无关用例（阶段4验证）。
7. docker-compose 中 mongodb 镜像仍为 mongo:4.4（原样保留），生产建议单独立项升级（涉及 init.sh mongosh 改造）。
