## 三、执行中发现并修复的缺陷（bug 清单）

### A. 主代码缺陷（测试驱动发现的真实行为偏差，已修复）

| # | 缺陷 | 根因 | 修复 | 风险评估 |
|---|---|---|---|---|
| B1 🔴 | browser 客户端 password grant 取 token 返回 401 invalid_client | Spring Authorization Server 默认客户端认证链不支持"公共客户端（NONE 方法）+ 仅 client_id"的 token 请求（PKCE 通道仅适用 authorization_code）；旧 spring-security-oauth2 天然支持 | 新增 grant/PasswordClientAuthenticationConverter + PasswordClientAuthenticationProvider，仅对显式注册为 NONE 方法的客户端放行，机密客户端绝不走此通道 | 低：纯增量扩展，未放宽任何已注册客户端的认证要求；AUTH-02/08 验证错误 secret 与未注册 client 仍 401 |
| B2 🔴 | password grant 不签发 refresh_token（与旧系统不一致，UI 无法续期） | 自定义 grant provider 沿用了 SAS 内置"NONE 客户端不发 refresh token"的约束 | Provider 中恢复 legacy parity：注册了 REFRESH_TOKEN grant 的客户端即签发；AUTH-05 验证轮换后旧 refresh 失效 | 低：与旧系统行为一致（旧 browser client 即 password+refresh_token） |
| B3 🔴 | 统计查询 findByIdAccount 在真实 Mongo 上抛 MappingException（"Couldn't find PersistentEntity for property @Id DataPointId"）——GET /statistics/current 与 findByAccountName 链路运行时必挂 | Spring Data MongoDB 4.x 将注册了自定义转换器的 DataPointId 视为简单类型，派生查询无法再解析 id.account 属性路径（2.x 可以）；纯 mock 测试无法暴露 | 改为显式 @Query("{'_id.account': ?0}") findByAccountName，生成的 Mongo 过滤条件与旧派生查询**完全相同**，零语义变更；同步更新 StatisticsServiceImpl 调用点 | 低：过滤条件逐字节等价；CVT-03 真实库往返 + AUTH/STA 全量回归通过。🔴 属统计查询链路，请人工复核该变更 |
